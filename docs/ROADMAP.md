# Toward the complete Tubular vision

The typed capability path is a working starting point, not the whole intended AAPI developer experience. This list is ordered by the gaps that matter most before adopting it for consequential work.

1. **Durable execution and recovery.** The typed path now uses the existing kernel for policy, exact approval, execution rechecks, receipts, and audit. State is still in memory. Define storage transactions, operation-key retention, lease-use concurrency, restart recovery, audit anchoring, and unknown-outcome reconciliation before consequential effects.
2. **Identity and context ownership.** Opaque host-created sessions now bind principals, leases, and selected provenance-bearing manifests. Supply real authentication, an authenticated exact-proposal review interface, revocation/session lifecycle, secret-safe ingestion, and provenance verification. Separate user-owned context from approved support context at the application boundary. Serenity remains a separate service.
3. **Broader policy and resources.** The current kernel enforces canonical workspace scopes. Design generalized resource resolvers, disclosure enforcement at actual egress, and adapter conformance checks. Handlers and their resource/effect declarations remain trusted code.
4. **Compiler and binding coverage.** Generated modules now import the intended handlers directly, carry source fingerprints, and support non-writing drift checks. Structural object intersections, readonly arrays, and object-only MCP output unions work. Recursive types, tuples, open dictionaries, generic/overloaded handlers, top-level input unions, and primitive brands remain unsupported. Add constructs only with matching runtime validation and lossless projections. Release builds still need dependency pinning and artifact provenance beyond self-consistent hashes.
5. **Transports and providers.** Typed MCP tools invoke the same runtime, but approval/resumption UI, MCP resources/prompts, provider adapters, HTTP endpoints, authentication, transport input/request limits, and applicable bearer audience validation remain host work. The OpenAPI projection describes a possible interface, not an implemented server or complete HTTP lifecycle protocol.
6. **Distribution and compatibility.** The check command now verifies packed-package exports, generated TypeScript bindings, CLI drift checks, runtime validation, and the governed example. The offline consumer reuses installed dependencies. Fresh dependency installation, supported-platform/Node-version matrices, release automation, compatibility guarantees, license selection, and publication remain open. No GitHub or publication changes are part of this work.

MCCP means Model Context & Convergence Protocol. The retained experimental prototype uses its own terminology and is not evidence of a finalized MCCP specification.
